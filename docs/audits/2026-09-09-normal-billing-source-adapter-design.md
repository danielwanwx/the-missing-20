Status: PROPOSED, not implemented. This follows accepted pure preview and the separately reviewed journal; it does not authorize an invoice insert/submit by itself. Scope stays R4 PO16/PR7, accepted1 Box out of ordered40, synthetic disclosed supplier bill50USD.

Implement one narrow reader that gathers actual PO and PR native documents, the native unnamed receipt-to-invoice mapper output, and complete related-document evidence for `validate_billing_preview`. Reuse the configured ERP transport; do not create a second authentication stack or use the legacy QA-release executor flow. Accept server-bound `SyntheticBillingBasis`, not arbitrary user paths, doctype strings or URLs. No create, update, delete, submit, payment, model invocation, approval or UI in this slice. Mapper POST is the existing read-only make_purchase_invoice method, with exact PR and filtered child, not document insertion.

Read PO/PR by exact identity and verify returned names. Discover Purchase Invoice and Purchase Receipt parent names using company+supplier filters, stable ordering and bounded pagination without creation-date or docstatus exclusions. Fetch every admitted parent and inspect native children; direct child REST is not assumed available. Include supplier bill-number collisions outside this PR, linked draft/submitted/cancelled/credit/mixed invoices and native PR returns. Do not reduce duplicate lookup to posted invoices. Preserve raw retrieved documents and ordered query evidence for later review.

Only declare lookup coverage complete when every page terminates, every named parent is fetched with matching identity/scope, and no page/request/parse/size guard failed. Repeated/duplicate pagination, malformed rows, denied parent reads, unknown status, exhausted page/document limits and timeout all yield explicit incomplete coverage and no READY proposal. Empty but complete is distinct from inaccessible or truncated. The reader must report the bounds actually used; hitting a bound is not end-of-list. Native documents and the envelope must remain unchanged after pure validation.

Return exact raw source inputs, timestamp, snapshot digest and the accepted preview result; do not claim a durable approval or writer grant from READY. Tests cover actual saved native PO/PR/mapper shape, pagination and bill collision on another receipt, linked drafts and returns, partial parent failure, repeated page, identity/scope mismatch and zero forbidden HTTP methods/endpoints. After independent review, run a single real read-only preflight on R4 and verify no new PI/stock/GL effect. Keep private evidence and all failed coverage outcomes.

A later phase-aware executor must refresh before effects and verify original commercial facts. The journal distinguishes volatile audit refresh from decisive change. Its `related_documents` commercial revision must not accidentally treat the already-authorized operation's own exact draft as unrelated new commercial evidence and permanently prevent first submit. The reader itself must never hide or exclude a supplied invoice name. Only after exact journal-bound draft readback may the executor classify that one expected own effect separately; any other related document, changed amount/identity, partial lookup or ambiguity holds further writes. This integration invariant requires dedicated tests before executor implementation/acceptance.

## Independent design gate

**APPROVED TO IMPLEMENT this narrow read adapter**, with the concrete contract below. This approval does not extend to an executor or a paid-model call. The accepted preview/journal do not relieve this adapter of proving actual lookup coverage.

Use one reader entry point accepting the server-bound basis and injected configured ERP transport. Return raw PO, PR, native mapper result, related-read envelope, evidence/query manifest and preview. Do not introduce an authentication framework, generic workflow layer, journal mutation or approval API. Mapper invocation must be allowlisted to the already verified native PR-to-PI method with the exact PR child; no arbitrary method/URL/doctype parameter reaches transport.

The related envelope must explicitly populate all three preview coverage flags: receipt_line_invoices, receipt_returns and bill_reference_collisions. Company/supplier-wide parent discovery and complete child inspection can establish them for the controlled demo; a PR-filtered invoice query alone cannot establish the last flag. Preserve draft, submitted, cancelled, return and same-bill-other-PR candidates. Native receipt returns use header return_against and/or source PO child links, not invented PI-style receipt-child fields. Never silently discard a document because its shape is inconvenient or its fetch failed.

Freeze stable pagination order, page size, page/document/response/time bounds in code/tests. Short terminal pages or explicit provider pagination evidence establish termination; reaching a guard, repeated pages, duplicate identities or inconsistent declarations yields incomplete coverage. Verify each fetched parent name, type and company/supplier against its discovery scope. Keep every source and failure in the private evidence manifest, including pages read before a failure. Incomplete preview outcome must be HOLD, never an empty-complete replacement or a READY result with an error attached.

At minimum offline tests must show: a same-reference invoice on another receipt is retained; a native PR return blocks; linked draft/cancelled/credit/mixed records are not status-filtered; a second-page candidate is found; partial parent failure, pagination repeat and cap exhaustion suppress every affected coverage claim; renamed or wrong-scope fetches fail closed; and source/mapper inputs remain unchanged by preview construction. Assert the exact permitted transport calls and zero insert/submit/update/delete/payment calls. The raw result must include the operation's own known draft if present; it must not accept an exclude-own-invoice option.

Own-draft classification remains a future phase-aware operation: only the immutable journal-bound exact name and bill/commercial facts can identify the expected effect. Keep its raw evidence and original/current audit snapshots, separate it from unrelated commercial changes only at that later boundary, and retain the first-submit fence. This read slice need not solve or expand that executor, but must avoid an irreversible fingerprint/filter contract that hides evidence or makes the expected transition indistinguishable from source tampering. A live read-only preflight follows implementation review, with the existing frozen R4 scope and no mutation.
