## Required corrections and precise interfaces

1. Preserve the current preview's raw-mapper admission behavior. The draft's statement that a raw mapper may have null bill fields must not weaken existing checks: absent fields are compatible with the actual native mapper; a supplied unknown/null/wrong reference currently fails the accepted preview. Run that original preview first and require READY, then clone the admitted mapper and add only the disclosed bill_no and bill_date. Validate the bound document with those exact expected fields. Do not overwrite a conflicting/unknown raw value before admission. Keep all 58 existing preview tests unchanged; add state/binding tests rather than rewriting earlier counterexamples to pass.
2. Use one shared pure commercial validator. The existing preview should delegate without changing its outcomes; explicit MAPPED/DRAFT/SUBMITTED modes add exact name/docstatus checks and required bound bill fields at the later stages. Preserve exact PO/PR child, quantities/conversion, currency, accounts, no-stock/no-payment/no-tax/no-return checks. Shared extraction should not duplicate commerce rules in a coordinator or replace structured validation with flags supplied by callers.
3. Keep commercial_version the existing source commercial fingerprint; do not derive it recursively from a request that itself contains commercial_version. Bind complete method/path/body plus digest to the immutable intent_id/intent_version and bill_digest separately before approval. The opaque token already binds that version. A changed payload requires allowed pre-insert reprepare/new version and invalidates the old token. No mutation of old version evidence is allowed.
4. claim_insert must accept no mapper/body override. In the existing immediate transaction it verifies the persisted request, its binding/digest and exact allowlist, and stores the exact outgoing request with the durable insert marker before returning it. Mutation of caller mappings after preparation or claim must not mutate stored/returned immutable evidence. claim_submit similarly uses only the persisted exact admitted draft document, with immutable first name and digest, to form POST `/api/method/frappe.client.submit` body `{doc: ...}` in the submit-marker transaction. The existing native client uses that full-document API, not a name-only request.
5. Migration is fail closed for both effects: old unbound intents remain readable but cannot newly approve or claim insert; old draft proofs without the exact canonical draft body/digest cannot claim submit either. Keep readback/recovery and prior effect evidence available. Missing request evidence is not permission to regenerate a body after a marker. Different draft identity/document digest conflicts retain first evidence and keep all future-write fences shut.

## Offline acceptance floor

Retain existing preview and journal regressions, including process race/restart, source-change/refusal/expiry, immutable name and submit-proof binding. Add tests for each allowed state and wrong state/name/bill; malformed or modified bound request/digest/path/method; source and request version mismatch; old-token rejection after reprepare; no body replacement after approval; immutable nested JSON after caller mutation; exact full insert/submit body surviving database reopen; and legacy unbound insert/submit denial. Assert there is no transport call in this slice. The new request type is a durable contract, not an in-process capability against arbitrary trusted-code forgery.

## Future coordinator boundaries retained, not implemented by this gate

Own-draft classification must operate on the full fresh raw source before sticky refresh_source recording. It may exclude only the exact uniquely readback-verified journal-bound draft from the comparison view, preserving the raw document/audit. All other changes remain decisive. PO/PR revisions remain strict; if actual draft creation changes them, retain the draft and stop, rather than silently clear source_changed. The posting_time-only comparison exception is narrowly conditioned on exact integer set_posting_time=0 in both documents; it never changes the frozen body or ignores other fields. Its implementation and actual mapper evidence require review in the coordinator stage, not this binding substage.

Financial closure must later establish exact-voucher GL debit SRBN50/credit Creditors50 with supplier identity on the payable row, no unexpected rows, complete empty PI SLE lookup and unchanged PR7 entry identities/quantities/values. Shared warehouse total balance is not the invariant. A submitted document alone cannot pass financial closure. Lost insert/submit acknowledgment must never reopen either attempt fence. Current user demo authorization remains applicable; an explicit product manager action is application authority, not a newly invented user permission loop.

No product file was changed and no model, ERP or other external call was made for this review. Scope approval is deliberately narrower than the full executor draft.
