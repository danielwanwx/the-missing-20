## Coherence and proof test

Scenes 01–08 can become one excellent workflow: detect the exception, inspect physical evidence, ask follow-ups, prepare a resolution, approve it, execute it, and verify native records. Scene 09 weakens that story if it changes to completed PO19 at the climax. A label would make the switch truthful, but truthfulness alone does not make two cases feel like one end-to-end result. The stronger cut ends on the verified outcome of the same eligible incident used in scenes 01–08.

The agent and AWS proof plan is directionally right but unproven. The final film needs to show natural prompts, visible tool use or sourced findings, a proposal grounded in policy, one real approval/execution transition, and readback with matching identifiers. The Bedrock insert should contain a request or trace correlation, model, and timestamp that connect it to the answer just shown. If only an application trace is available, describe it as an application invocation trace rather than proof of a specific Bedrock request.

The motion plan is disciplined: 1.5–2× enlargement, stable holds, no reading during scroll, and 7–9 seconds for meaningful records. Those are good production rules. At 4:50, though, the film has only ten seconds of format margin, while scenes 05–08 depend on real latency and legible holds. A shorter target protects the evidence instead of forcing rushed motion.

Remove the separate-case branch and trim repeated app naming rather than shortening evidence holds. Show each system name as its matching record appears. Use the recovered time for the real approval transition, readable identifiers, and final readback.
